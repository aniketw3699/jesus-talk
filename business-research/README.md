# Business Research Ledger

Last updated: 2026-09-29

## Purpose

This branch is the permanent memory for the software-business search.

Before suggesting or researching a software category, read the files in this folder first.

**Do not research a category already listed as REJECTED or ALREADY CHECKED unless the user explicitly asks to reopen it.**

After every serious category investigation:
1. Add the category to the ledger.
2. Record the status: REJECTED / ALREADY CHECKED / NEAR MISS / ACTIVE KILL-TEST / GO / MODIFY.
3. Record the main competitors and decisive reason.
4. Record the date.
5. Only then continue searching new categories.

## Core goal

Find a global software business with:
- existing paying demand;
- a real painful problem;
- strong user pull, not total dependence on advertising;
- low or near-zero operating cost from the developer side;
- processing preferably on the user's device/browser/desktop;
- no major recurring GPU, storage, or server burden;
- useful free acquisition tools where possible;
- clear monetisation;
- plausible Google/search or product-led acquisition;
- meaningful differentiation;
- a moat stronger than a cosmetic feature;
- potential to become an important player in its category.

Current acceptance threshold is approximately **60–70% fit**, not an impossible 100%.

## Non-negotiable process

**Do not build first.**

Before coding, investigate:
market size, growth, leaders, pricing, revenue/profit where available, free/open-source substitutes, customer complaints, why customers pay, feature coverage, differentiation, copyability, local-processing feasibility, infrastructure cost, SEO/search demand, product-led acquisition, pricing, conversion logic, unit economics, user pull, and realistic category position.

The PDF-tool experience is the warning: a technically good product can still be a weak business when strong free substitutes already satisfy most users.
